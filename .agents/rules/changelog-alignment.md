# Changelog alignment

`CHANGELOG.md` is **generated by Release Please** from conventional PR titles (see `docs/versioning.md`). Do not edit it by hand and do not add an `Unreleased` section or a table of contents to it.

When you modify this repository in a way that is **not purely trivial** (behavior, public API of scripts, templates, CI, pins, baselines, docs that describe shipped behavior, or release flow):

1. **Write the PR title as the changelog entry**: `type(scope): summary` in plain language. `feat:` and `fix:` open a release; `ci:`, `docs:`, `chore:` and similar do not, and `!` marks a breaking change.
2. **Describe migration impact in the PR description** when a template, `copier.yml`, a reusable workflow input or a pin changes, and in `docs/migration-guide.md` when adopters must act.
3. **Never bump `STANDARDS_VERSION`, marked pins, tags or releases by hand**; the Release Please PR owns them.

If you are **aligning another repo** to these standards, update that consumer's own release notes when your work there is user-visible.
